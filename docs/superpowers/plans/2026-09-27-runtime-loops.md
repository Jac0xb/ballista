# Runtime loops: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to carry out this plan task by task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add count loops (`REPEAT`, opcode 61) and let a template hold up to eight top-level
loops, run one after another. Each part is verified at finalize, executed on chain, authorable
from TypeScript and from the Rust `ProgramBuilder`, generated by the property tests, and covered
end to end under Mollusk. This is section 2 of
`docs/superpowers/specs/2026-09-26-runtime-extensions-design.md`.

**Architecture:**
- **The opcode.** `REPEAT` fields:
  - `a`: body length, 1 to 255;
  - `b`: the `u64` count register, read once when the loop starts;
  - `c`: the static maximum, 1 to 255;
  - immediate: the carry mask, as for `FOREACH`.

  A count above `c` fails the run with `LoopCountExceeded` (6022, context: the program counter).
- **The verifier.** The `in_loop` flag becomes `LoopScope { Root, Rows, Count }`, with two
  questions:
  - `in_loop()`: is `LOOP_INDEX` allowed?
  - `in_row_loop()`: are row accounts and row inputs allowed?

  The loop rules:
  - Up to `MAX_LOOPS` (8) loops, never nested.
  - A batch needs at least one `FOREACH`.
  - A row named inside a `REPEAT` body fails with `InvalidLoop` (6129).
  - The worst case adds each loop's body invocations times its maximum to the invocations
    outside loops, and must stay at or below 64.
- **The executor.** One `Loop` state covers both kinds:
  - The kind decides only how a loop starts: its pass count, its first row base, and its stride.
    A `REPEAT` has stride zero and the row base `NO_ROWS`.
  - The register snapshot moves into `Scratch`, which already holds the run's reusable buffers.
    The first loop allocates it and every later loop copies into it.
  - Loop entry leaves the hot path. `execute_instruction` already fails an opcode it does not
    run, before reading any operand. `dispatch` stops testing every instruction for `FOREACH`
    and instead recognises both loop opcodes on its failure branch, at the root.
  - Neither `execute_instruction`'s match nor `Machine` changes.
- **TypeScript.**
  - `step.repeat(count, steps, { max, carry?, label? })`.
  - The compiler tracks which loop kind a step sits in.
  - The worst-case count and `inspectTemplate` handle `REPEAT` and several loops.
  - A pre-existing bug is fixed: two carried variables that start from the same literal shared
    one register. With several loops that is the normal case, so each carried variable now gets
    a register of its own when it needs one.

**Tech stack:**
- Rust: a `no_std` SBF program on pinocchio 0.11, and the shared `ballista-common` crate.
- TypeScript SDK: Zod and vitest.
- Mollusk 0.14 integration suite; Certora specs.

**Base:**
- Phase 1 (math) is complete on `claude/runtime-extensions`; this plan was written at `dedc168`.
  - Create branch `claude/runtime-loops` from its tip, in worktree
    `.claude/worktrees/runtime-loops`.
  - Line numbers below refer to `dedc168`. All paths are relative to the worktree root.
- Phase 1 may still move the per-instruction handler to a `step(&mut Machine, …)` shape, with
  `extended_instruction(machine, instruction, loop_context)` writing its own destination.
  - This plan changes neither `execute_instruction`'s match nor `extended_instruction`.
  - Where it quotes the handler call in `dispatch`, keep whatever call the branch has. Task 2

- The numbers are pre-assigned: opcode `OP_REPEAT = 61`, runtime error `LoopCountExceeded = 6022`

  - Phases 3 and 4 are built in parallel. They take opcodes 62–74, runtime errors 6023–6024 and

**Conventions:**
- Keep the surrounding style: doc comments that explain why, `#[inline(never)]` for heavy
  helpers reached from the dispatch loop, and `RunResult`/`BallistaError` for failures.
- **Freeze the outer match** of `execute_instruction`: no new arms, guards or `if`s. SBF has no
  indirect jump, so the match compiles to a tree of comparisons. LLVM folds any opcode test into
  that tree, and every existing opcode pays for it.

  - `run, payroll 8 rows` rises by about 18. It has too few instructions for the cheaper

### Task 2: One loop state for both kinds, entered off the hot path

**Files:**
- Modify: `common/src/template/builder.rs`: `repeat` after `for_each` (around line 358), and a test.
- Modify: `programs/ballista/src/processor/execute.rs`:
  - `Scratch` (131–156) and `Scratch::new` (170–192);
  - `encode_event`'s doc comment (266);
  - `dispatch` (587–635);
  - `Batch`, `enter_batch`, `next_iteration`, `finish_batch` (646–760), all replaced;
  - the tests.

Why the design is shaped this way. These figures come from a prototype on this base:
- **The snapshot lives in `Scratch`, not in `Machine`.** Adding a field to `Machine` changes its
  layout, and with it the dispatch loop's register allocation. That alone cost 1,686 units over
  the nine ceiling cases, including 72 on a template with no loop at all. As a `Scratch` field it
  cost nothing.
- **Loop entry moves to the failure branch.** `dispatch` used to compare every instruction's
  opcode with `FOREACH`, at about two SBF instructions each. `execute_instruction` already fails
  both loop opcodes, before reading an operand, through its `_` arm. Recognising them there, at
  the root, makes every other instruction cheaper: −932 units over the nine cases and −4,751 over
  the 32 examples. The variants are measured again in Task 9.
- **No `RunError` variant.** The failure branch already has the instruction, so its opcode is the
  signal. `RunResult<()>` stays the 12 bytes that the Certora summaries assume. `execute_instruction`
  keeps its contract: every opcode it does not run fails as an invalid program.

```rust
    /// Emits a REPEAT whose body is produced by `body` and returns the REPEAT's index. The body
    /// runs as many times as the `u64` in register `count` holds when the loop starts; a count
    /// above `max` fails the run.
    pub fn repeat(
        &mut self,
        count: u8,
        max: u8,
        carry_mask: u64,
        body: impl FnOnce(&mut Self),
    ) -> usize {
        let index = self.emit(record(OP_REPEAT, NO_INDEX, 0, count, max, 0, carry_mask));
        body(self);
        let body_len = (self.instructions.len() - index - 1) as u8;
        self.instructions[index].a = body_len;
        index
    }
```

```rust
/// The row base of a count loop, which has no rows. It is far past any account index, so a row
/// account named there resolves to nothing, though the verifier already rejects one; and far
/// below `usize::MAX`, so adding a row offset cannot wrap it back into range.
pub const NO_ROWS: usize = usize::MAX / 2;

/// A loop in progress: a FOREACH over the batch rows or a REPEAT over a count. The kind decides
/// only how the loop starts, as its pass count, first row base and stride, so it is not stored.
struct Loop {
    body_start: usize,
    body_end: usize,
    /// Passes to run: one per batch row for FOREACH, the count for REPEAT.
    passes: usize,
    /// Added to `row_base` after each pass: the batch stride for FOREACH, and zero for REPEAT,
    /// whose base stays `NO_ROWS`.
    stride: usize,
    /// The registers the carry mask names, in ascending order: the first `carried_len` entries.
    /// Listed once at loop entry so a pass copies just these instead of testing every register.
    carried: [u8; MAX_REGISTERS],
    carried_len: usize,
    /// Whether the body names a destination outside the carry mask. When it does not, every
    /// register already equals its snapshot at the end of a pass (the carried ones were just
    /// copied into it), so the restore would copy the file onto itself and is skipped.
    restore: bool,
    iteration: usize,
    row_base: usize,
}

/// Starts the loop at `pc`: checks its body range, finds how many passes it makes, snapshots the
/// registers, and decides what the loop's invocations can reuse between passes. With a pass to
/// run, fills `slot` in place and returns the body's range; with none, leaves it empty and
/// returns the code after the loop.
#[inline(never)]
fn enter_loop(
    machine: &mut Machine<'_, '_>,
    pc: usize,
    instruction: &InstructionRecord,
    slot: &mut Option<Loop>,
) -> Result<(usize, usize), ProgramError> {
    let program = machine.program;
    let body_start = pc + 1;
    let body_end = body_start
        .checked_add(instruction.a as usize)
        .filter(|end| *end <= program.instructions.len())
        .ok_or_else(|| RunError::from(BallistaError::InvalidTemplateProgram).at(pc, instruction))?;
    // FOREACH makes one pass per batch row, starting at the first row. REPEAT makes as many
    // passes as its count register holds now, read once so the body cannot change it, and has
    // no rows.
    let (passes, row_base, stride) = if instruction.opcode == OP_FOREACH {
        (
            machine.iterations,
            program.header.fixed_account_count(),
            program.header.batch_stride(),
        )
    } else {
        let count = loop_count(machine.registers, instruction)
            .map_err(|error| error.at(pc, instruction))?;
        (count, NO_ROWS, 0)
    };
    // Registers written inside the body are discarded after each pass, except the ones named in
    // the carry mask, which flow into the next pass and out of the loop.
    let carry = instruction.immediate();
    let register_count = machine.registers.len();
    // Every write goes through an instruction's `dst`, whatever its opcode, so a body whose
    // destinations are all carried registers, or not registers at all, leaves nothing to restore.
    let restore = program.instructions[body_start..body_end].iter().any(|record| {
        let dst = record.dst as usize;
        dst < register_count && (dst >= MAX_REGISTERS || carry & (1u64 << dst) == 0)
    });
    let (cache_cpi, data_invariant) =
        loop_cache_plan(program, &program.instructions[body_start..body_end]);
    machine.scratch.cache_cpi = cache_cpi;
    machine.scratch.data_invariant = data_invariant;
    machine.scratch.built = false;
    if passes == 0 {
        finish_loop(machine);
        return Ok((body_end, program.instructions.len()));
    }
    // `run` allocates exactly the header's one-byte count of registers. Sliced by that count
    // rather than by the file's own length, the copy is visibly small and needs no overflow
    // check, which on SBF is a 128-bit multiply.
    let registers = &machine.registers[..program.header.register_count()];
    let snapshot = &mut machine.scratch.snapshot;
    if snapshot.len() == registers.len() {
        snapshot.copy_from_slice(registers);
    } else {
        *snapshot = registers.to_vec();
    }
    // Built in place: moving a finished loop into the slot would copy it with a syscall.
    let active = slot.insert(Loop {
        body_start,
        body_end,
        passes,
        stride,
        carried: [0; MAX_REGISTERS],
        carried_len: 0,
        restore,
        iteration: 0,
        row_base,
    });
    for register in 0..register_count.min(MAX_REGISTERS) {
        if carry & (1u64 << register) != 0 {
            active.carried[active.carried_len] = register as u8;
            active.carried_len += 1;
        }
    }
    // The first pass starts from registers equal to the snapshot, so it needs no restore.
    Ok((body_start, body_end))
}

/// The pass count a REPEAT names: register `b`, which must hold a `u64` no greater than the
/// static maximum in `c`.
#[inline(always)]
fn loop_count(registers: &[RuntimeValue<'_>], instruction: &InstructionRecord) -> RunResult<usize> {
    let count = match registers.get(instruction.b as usize) {
        Some(RuntimeValue::U64(count)) => *count,
        Some(RuntimeValue::Unset) | None => return Err(BallistaError::InvalidRegister.into()),
        Some(_) => return Err(BallistaError::TypeMismatch.into()),
    };
    if count > instruction.c as u64 {
        return Err(BallistaError::LoopCountExceeded.into());
    }
    // At most 255, so it fits.
    Ok(count as usize)
}

/// Ends one pass over a loop body: keeps the carried registers, then either restores the
/// snapshot for the next pass and returns its loop context, or restores it for the code after the
/// loop and returns `None`.
#[inline(never)]
fn next_iteration(machine: &mut Machine<'_, '_>, active: &mut Loop) -> Option<(usize, usize)> {
    let snapshot = &mut machine.scratch.snapshot;
    for &register in &active.carried[..active.carried_len] {
        let register = register as usize;
        snapshot[register] = machine.registers[register];
    }
    if active.restore {
        machine.registers.copy_from_slice(snapshot);
    }
    // Both stay below 256 passes and the runtime account count.
    active.iteration = active.iteration.wrapping_add(1);
    if active.iteration < active.passes {
        // Row `n` starts at `fixed + n * stride`; stepping by the stride avoids a checked
        // multiplication, which SBF implements with a 128-bit multiply routine of about fifty
        // instructions. A REPEAT's stride is zero.
        active.row_base = active.row_base.wrapping_add(active.stride);
        return Some((active.iteration, active.row_base));
    }
    finish_loop(machine);
    None
}

/// Clears the loop's invocation cache once the loop is over.
fn finish_loop(machine: &mut Machine<'_, '_>) {
    machine.scratch.cache_cpi = None;
    machine.scratch.built = false;
    machine.scratch.data_invariant = false;
}
```

```rust
            body_registers.push(sum, kind);
            body.mov(register, sum);

        // body with a requirement that always holds to keep it non-empty.
        let always = body.const_bool(true);
        body.require(always);
    };
    match count {
        Some((count, max)) => builder.repeat(count, max, carry_mask, body),
        None => builder.for_each(carry_mask, body),
    };
}
```

```ts
function countCpis(steps: Step[]): number {
  return steps.reduce((total, current) => {
    if (current.kind === 'invoke') return total + 1;
    if (current.kind === 'forEach' || current.kind === 'repeat') return total + countCpis(current.steps);
    return total;

/**

 * batch's for a `forEach` and its own `max` for a `repeat`, and every other invoke once.

function worstCaseCpis(steps: Step[], batchMaxIterations: number): number {
  return steps.reduce((total, current) => {
    if (current.kind === 'forEach') return total + countCpis(current.steps) * batchMaxIterations;
    if (current.kind === 'repeat') return total + countCpis(current.steps) * current.max;
    return total + countCpis([current]);
```

### Task 6: Give every carried variable a register of its own

This is a pre-existing compiler bug that several loops would hit all the time.
- **The cause.** `step.let('sum', expression.u64(0))` binds `sum` to the hoisted register of the
  constant 0. A second `step.let('count', expression.u64(0))` binds `count` to that same register.
- **The failure.** Carry both, and each `assign` rewrites the one register: `sum`, `count` and
  every later read of the constant 0 see the same value.
- **Where it shows.** Before this phase it took two accumulators with the same starting literal
  in one loop. With several loops it takes one accumulator per loop, which is the obvious way to
  write them. The `loops` fixture in Task 7 is exactly that.
- **The fix.** At loop entry, a carried variable whose register anything else reads is copied
  into a fresh register first. Only then does something read it. When one `let` alone reads a
  hoisted constant or input, nothing is copied, so no existing fixture or example changes.

```ts
 * appears in the steps. A hoisted register that one appearance alone reads can be handed to a
 * loop-carried variable; one that more read cannot.

function countUses(value: unknown, into = new Map<string, number>()): Map<string, number> {
  if (Array.isArray(value)) {
    for (const item of value) countUses(item, into);
    return into;
  }
  if (value === null || typeof value !== 'object') return into;
  const record = value as Record<string, unknown>;
  const inner = record.value as Literal | undefined;
```

```ts
   * Whether anything besides variable `name` reads `register`: another variable, or a hoisted

  sharesRegister(name: string, register: number, bindings: Bindings): boolean {
```
